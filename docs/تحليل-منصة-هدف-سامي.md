## 1. ما هو المشروع الحالي فعلًا؟

ليس مشروعًا فارغًا ولا مشروع «هدف سامي». هو **منصة عربية RTL كاملة للتدريب على اختبار
الرخصة المهنية للمعلمين**، مبنية بـ **PHP 8 + MySQL بدون أي إطار عمل أو Composer**،
وتعمل على XAMPP والاستضافة المشتركة والسيرفرات الخاصة.

**أرقام فعلية (محسوبة، لا تقديرية):**

| المؤشر | القيمة |
|---|---|
| ملفات PHP | **151** ملفًا |
| إجمالي أسطر PHP | **25,306** سطرًا |
| جداول قاعدة البيانات | **27** جدولًا |
| العروض (Views) | **3** (`vw_active_subscriptions`, `vw_question_stats`, `vw_category_performance`) |
| حجم `database.sql` | 83 KB (مخطط + بيانات أولية) |
| صفحات الإدارة | 17 شاشة |
| البنية | `src/` (طبقة منطق) + `views/` (قوالب) + مجلدات الصفحات + `api/` + `tools/` + `tests/` |

## 2. ما يمكن إعادة استخدامه كما هو (مكسب كبير)

هذه أجزاء **مكتملة ومختبرة منطقيًا** وتغطي جزءًا كبيرًا من متطلباتك (أقسام 6، 10، 11، 12، 13، 18، 19، 20، 21):

| الوحدة | الحالة الفعلية |
|---|---|
| **الاتصال بقاعدة البيانات** | `src/Database.php` — PDO + Prepared Statements فقط |
| **المصادقة** | `src/Auth.php`: Argon2id/bcrypt، تسجيل دخول بالبريد أو الجوال، Rate Limiting، قفل مؤقت، Remember Me ببصمة جهاز، استعادة كلمة مرور برموز `password_resets` |
| **الأمن العام** | `src/Security.php`: CSRF، تحديد المعدل، رفع ملفات آمن (فلترة امتداد + رفض `php/phtml/phar`)، تشفير AES-256-GCM للمفاتيح، ترويسات أمان |
| **الصلاحيات** | أدوار `student / admin / supervisor` + `requireAdmin() / requireSuperAdmin()` على الخادم |
| **سجل التدقيق** | `audit_logs` + `src/Audit.php` |
| **بنك الأسئلة** | `questions` + `src/Repositories/QuestionRepository.php` (بحث/تصفية/ترقيم) |
| **استيراد الأسئلة** | `src/QuestionImporter.php` + `PdfExtractor.php`: PDF/TXT/CSV/JSON → **جدول مراجعة** → اعتماد يدوي، كشف تكرار، وسم «بلا إجابة» **بدون تخمين** |
| **محرك الاختبارات** | `src/Services/ExamEngine.php`: بناء اختبار، مؤقّت **محسوب على الخادم**، حفظ إجابة تدريجي (`api/exam/save-answer.php`)، تعليم للمراجعة، إرسال نهائي، إغلاق المحاولات المتأخرة |
| **النتائج والتحليل** | تقرير، تحليل لكل مجال، اتجاه الدرجات، نقاط قوة/ضعف، توصيات، «نسبة جاهزية»، `user_category_stats` |
| **الاشتراكات** | `subscription_plans` (سعر/مدة/مسارات/مزايا) + `subscriptions` (pending→active→expired) + `SubscriptionService` |
| **المدفوعات** | `src/Payments/`: واجهة `PaymentGateway` + **Moyasar** + **MyFatoorah** + يدوي، مع `api/payments/callback.php` يتحقق من **التوقيع (HMAC-SHA256)** و**المبلغ** ورقم الطلب قبل التفعيل، ويمنع التفعيل المكرر |
| **الإشعارات** | داخلية + بريد + تلجرام (ربط طوعي برمز مشفّر يُستهلك مرة واحدة) |
| **التثبيت والنشر** | `install.php` معالج رسومي، `tools/install-cli.php`، `tools/cron.php`، `tools/build-package.php`، `docs/التثبيت-على-سيرفر.md` |
| **الاختبارات** | `tests/lint.php` (فحص صياغة كل الملفات)، `tests/run.php` (اختبارات منطق على قاعدة وهمية)، `tools/dev/smoke.php` (فحص دخاني لكل الصفحات) |

## 4. التصور المعماري المقترح

### المبدأ الحاكم
**إعادة التوظيف قبل إعادة الكتابة.** الكود الحالي يحقق ~60–70% من متطلباتك (الأصعب أمنيًا: الدفع،
الاختبارات، الاستيراد، التدقيق). إعادة بنائه من الصفر = تكلفة عالية ومخاطرة أمنية أعلى.

### ثلاثة خيارات

| الخيار | الوصف | التكلفة | المخاطر |
|---|---|---|---|
| **أ (توصيتي)** | **نفس الكود ← منصة هدف سامي**: إعادة توظيف `src/` كما هو + توحيد الهوية والتصنيفات في قاعدة البيانات + إضافة الوحدات الناقصة (دروس، فيديو، ولي أمر، خطط، ثيم) | متوسطة | منخفضة — نبني على كود مختبر |
| **ب** | **نفس الكود يخدم المنتجين**: نُبقي مسارات الرخصة ونضيف مساري القدرات والتحصيلي، والهوية/الثيم تُدار من لوحة الإدارة | متوسطة–مرتفعة | تعقيد الصلاحيات والاشتراكات؛ يحتاج اختبارات أوسع |
| **ج** | **مشروع جديد من الصفر** داخل المستودع | مرتفعة جدًا | إعادة اختراع الدفع/الاختبارات/الاستيراد = مخاطرة أمنية عالية |

### البنية المقترحة (تطوير تدريجي للقائمة، بلا هدم)

```
src/
├── Storage/                  ← طبقة تخزين مجردة (جديدة - قسم 31)
│   ├── StorageDriver.php     (واجهة: put/get/url/delete)
│   ├── LocalDriver.php       (خادم المنصة + روابط مؤقتة موقّعة)
│   ├── GoogleDriveDriver.php (OAuth2، رموز على الخادم فقط)
│   └── StorageManager.php
├── Services/
│   ├── BrandingService.php   ← (جديد) الشعار/الألوان/الخطوط + توليد CSS Variables
│   ├── LessonService.php     ← (جديد) الدروس/المرفقات
│   ├── VideoService.php      ← (جديد) الفيديو + تقدّم المشاهدة
│   ├── StudyPlanService.php  ← (جديد) الخطة الدراسية
│   ├── ParentService.php     ← (جديد) ربط ولي الأمر + موافقة موثّقة
│   └── RecommendationService ← (موجود جزئيًا في StatisticsService) محرك قواعد
└── ... (الباقي كما هو)
```

**جداول جديدة مقترحة** (إضافات على الـ27 الحالية، لا تعديل عليها إلا بالزيادة):
`subjects` · `units` · `lessons` · `lesson_attachments` · `videos` · `video_progress`
· `lesson_progress` · `study_plans` · `study_plan_items` · `parent_student_links`
· `parent_consents` · `question_tags` + `question_tag_map` · `branding_settings`
· `api_tokens` (لتطبيقات الجوال مستقبلًا)

**حسابات الأدوار:** إضافة `parent` و`teacher` إلى `users.role` (توسيع ENUM بترحيل آمن).

## 7. ما لم أتحقق منه بعد (أمانة علمية)

- **لا يوجد PHP ولا MySQL في بيئة العمل هذه** → لم أشغّل `tests/run.php` أو `tools/dev/smoke.php`،
  ولم أفتح المنصة في متصفح. تقييمي مبني على **قراءة الكود والمخطط الفعلي**، لا على تشغيل.
- لم أراجع كل سطر من الـ25,306 سطرًا؛ راجعت طبقة المنطق (`src/`) والمخطط (`database.sql`) ونقاط الدفع والاختبارات.
- أول تشغيل فعلي سيكون على بيئتك (XAMPP) أو عبر معاينة تصميم ثابتة إن رغبت.

## 8. افتراضات مؤقتة (قابلة للتغيير بعد إجابتك)

1. التقنية تبقى **PHP 8 + MySQL + PDO بدون إطار عمل** (لا تغيير إلا بموافقتك).
2. لن أربط أي خدمة خارجية مدفوعة أو أنشئ حسابات أو أنشر ملفات دون موافقتك الصريحة.
3. لن أملأ قاعدة البيانات بأسئلة وهمية للوصول إلى 10,000 سؤال.
4. كل التصنيفات «تنظيمية مرنة» ولا تُمثّل التوزيع الرسمي لاختبار قياس.
5. بوابات الدفع ستُترك **معطّلة بمفاتيح فارغة** حتى تزوّدني بحساب تاجر.
